Why private

If the useful context is sensitive, the data boundary is not a detail.

  • PII and client data need control: names, emails, contracts, meeting notes, and customer records should not be pasted into generic tools without clear boundaries.
  • Private deployment is an architecture choice: run in a private cloud, EU-controlled environment, or on-prem setup when the workflow requires it.
  • Not every step needs a frontier model: routine extraction, classification, routing, and structured summaries can often use smaller controlled models at lower cost.
  • Audit posture matters: every generated answer is designed to carry citations back to the notes, emails, documents, or records it used.
  • You own the system: database, artifacts, prompts, deployment, and model-routing decisions stay under your control.

Open-source reference architecture

Useful as a blueprint, intentionally not a turnkey product.

The repository shows the shape of a private company memory layer: ingestion, normalization, retrieval, citation validation, guided workflows, anonymous demo sessions, and a deployment path.

It is useful as a blueprint, but it is not a finished product for real client data. Real deployments need system access, permissions, data-quality review, privacy boundaries, monitoring, and a workflow-specific implementation plan.
